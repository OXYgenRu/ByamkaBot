# ТЗ для прототипа

## Цель

Собрать минимальный рабочий прототип Telegram-бота на Python, который может быть полноценным участником групповых чатов и в дальнейшем расширяться до агентной системы с памятью, инструментами, роутингом, юмором и внутренними интересами.

## Что пользователь явно запросил изначально

1. Хранить сообщения.
2. Запускать локальную LLM через Ollama.
3. Не переполнять контекст.
4. Иметь настройки, сколько токенов оставлять под ответ.
5. Учитывать, что thinking trace/reasoning ест токены.
6. Поддерживать много чатов одновременно.
7. Сжимать контекст старых сообщений.
8. Использовать векторную базу фактов.
9. Доставать факты из памяти.
10. Решать, нужно ли сейчас входить в диалог.
11. Иметь готовую базу под инструменты.
12. Быть модульным.
13. Богато настраиваться через конфиги.
14. Быть минимально рабочим прототипом, а не только схемой.

## Новое ТЗ этой итерации

1. Добавить внутренние интересы бота.
2. Интересы должны строиться на seeded Perlin-like шуме по embedding-пространству.
3. Интерес должен влиять на поведение, но не ломать социальную уместность.
4. Добавить эволюцию интересов: повторяющиеся похожие темы должны усиливать learned interest.
5. Добавить 2D fingerprint-картинку, которая визуализирует характер seed-а.
6. Добавить второй router после подтягивания фактов из памяти, чтобы бот мог передумать и промолчать.
7. Описать изменения в Markdown-документации.
8. Просмотреть и проверить код на корректность.

## Что пользователь мог не упомянуть, но нужно для рабочего прототипа

### 1. Ограничения Telegram Privacy Mode

В группах бот может не видеть все сообщения, если у него включён Privacy Mode. Это важно для "полноценного участника чата".

### 2. Rate limiting и антиспам

Бот не должен отвечать на всё подряд. Нужны:

- cooldown между ответами;
- лимит на последовательные ответы;
- порог уверенности роутера;
- режим "почти всегда отвечать", если есть reply/mention.

### 3. Персональные и групповые границы памяти

Факты должны иметь scope:

- глобальный;
- по чату;
- по пользователю.

В прототипе автоматические факты по умолчанию пишутся только в текущий `chat_id`, чтобы не смешивать контексты разных чатов. Глобальные auto facts можно разрешить только явно через конфиг.

### 4. Защита от нестабильного JSON модели

Router, post-memory router и tool planner возвращают JSON по схеме. Нужно уметь:

- парсить JSON;
- иметь fallback;
- не падать, если модель вернула мусор.

### 5. Tool permissions

Инструменты делятся на safe и side-effect. В прототипе запускаются только safe-инструменты.

### 6. Логи и rquid

Для отладки нужен request id на каждое входящее сообщение.

### 7. Идемпотентное сохранение сообщений

Telegram может присылать повторы. Нужен unique key `(chat_id, telegram_message_id)`.

### 8. Деградация при недоступности Ollama/Qdrant

Прототип должен логировать ошибку и не ломать весь процесс.

### 9. Интересы не должны становиться спамом

Внутренний интерес — это bias. Он может снизить порог ответа или усилить запоминание, но не должен заставлять бота влезать в чужой разговор без повода.

## Минимальная функциональная спецификация

### Message storage

- SQLite.
- Таблица `messages`.
- Таблица `chat_summaries`.
- Таблица `facts`.
- Таблица `tool_events`.
- Таблица `interest_observations`.
- Таблица `interest_topics`.

### LLM

- Ollama `/api/chat`.
- Ollama `/api/embed` для embeddings.
- Structured JSON через `format`.
- Очистка `<think>...</think>`.

### Context budget

- Грубая оценка токенов.
- Резерв под thinking.
- Резерв под видимый ответ.
- Старые сообщения заменяются summary.
- Последние сообщения добавляются до исчерпания бюджета.

### Summarization

- Если старых несжатых сообщений больше порога, они сжимаются.
- Summary пишется в `chat_summaries`.
- Сжатые сообщения помечаются `is_summarized=1`.

### Vector memory

- Qdrant local mode.
- Коллекция `bot_facts`.
- Embeddings из Ollama.
- Поиск фактов по текущему сообщению.

### Interest engine

- Embedding сообщения проецируется в малое латентное пространство.
- По latent-вектору считается seeded Perlin-like профиль интереса.
- Профиль содержит `innate_interest`, `learned_interest`, `final_interest`, `curiosity`, `humor`, `memory`, `reply`, `novelty`.
- Наблюдения пишутся в `interest_observations`.
- Повторяющиеся похожие темы усиливают записи в `interest_topics`.
- `/fingerprint` генерирует SVG fingerprint seed-а.
- `/interests` показывает learned interests текущего чата.

### Routing

- Первый router:
  - `ignore`;
  - `reply`;
  - `tool_reply`;
  - `ask_clarify`.
- Второй router после памяти:
  - может вернуть `ignore`, если ответ стал неуместным после анализа фактов;
  - по умолчанию не игнорирует прямые обращения.

### Tools

- Tool registry.
- Safe calculator.
- Memory search tool.
- Tool planner через LLM JSON.

## Нефункциональные требования

- Python 3.11+.
- Асинхронная архитектура.
- Модульность.
- Конфигурация через YAML + `.env`.
- Простая локальная установка.
- Возможность заменить модель/векторную БД/адаптер Telegram.

## Дополнительное ТЗ этой итерации: анти-зацикливание интересов

После тестов обнаружилась проблема: если seeded noise даёт высокую привлекательность некоторой семантической зоне, бот может начать слишком часто возвращаться к одной и той же теме.

Требования доработки:

1. Добавить cooldown на похожие темы.
2. Ограничить вклад innate interest, чтобы врождённый шум был только фоновым bias.
3. Добавить novelty penalty для повторяющихся тем.
4. Сделать learned-interest двусторонним: он может расти, но также должен затухать при повторении и низкой новизне.
5. Обновить документацию.

Реализовано в:

```text
bot_app/personality/interest_field.py
bot_app/personality/interest_engine.py
bot_app/core/router.py
bot_app/core/context_builder.py
config/config.example.yaml
docs/ANTI_LOOP_CHANGES.md
```

## Дополнение: offline-импорт Telegram JSON

Добавлен отдельный ingest-процесс для Telegram Desktop JSON export. Он нужен, чтобы бот мог получить исторический контекст чата без fine-tuning модели.

Требования к импорту:

- пользователь явно задаёт `target_chat_id`, на который повлияет история;
- поддерживаются single-chat export и full export с `chats.list`;
- импорт должен показывать прогресс;
- импорт должен быть идемпотентным по сообщениям;
- история должна превращаться в сообщения, summaries, факты, правила чата, learned interests, локальные темы и шутки;
- итогом должна быть статистика влияния на бота.

Реализация:

- `scripts/import_telegram_export.py` — CLI;
- `bot_app/importers/telegram_export.py` — importer;
- `telegram_import` в YAML-конфиге;
- `docs/TELEGRAM_IMPORT.md` — инструкция;
- `docs/TELEGRAM_IMPORT_TZ.md` — отдельное ТЗ импорта.
